## Le problème du financement OSS

GitHub Sponsors est gratuit et utile, mais limité : juste du recurring sponsorship. Beaucoup de patterns économiques OSS modernes ne sont pas couverts.

Polar.sh étend les options pour les mainteneurs :

- **Recurring sponsors** : abonnement mensuel ou annuel.
- **Premium tiers** : badges Discord, accès privé, support prioritaire.
- **Issue bounties** : un utilisateur veut un bug fixé ? Il met un bounty, un dev le claim.
- **Subscriptions** : monétiser des features premium, des docs avancées.
- **One-time purchases** : pour de gros sponsors ponctuels.

## Comment ça se distingue

GitHub Sponsors = juste du don récurrent. Polar.sh = plateforme de monétisation OSS structurée.

Workflow typique :

1. Vous créez votre repo sur Polar.sh, lié à votre GitHub.
2. Configurez les tiers (free, $5/mois, $50/mois, etc.).
3. Configurez des "deals" sur certaines issues (bounty).
4. Les sponsors paient via Polar, vous recevez les fonds (Stripe Connect).

## Bonus : monétiser les milestones

Vous pouvez vendre des "early access" à une feature en développement. Les sponsors qui paient un tier obtiennent accès anticipé. Cela transforme le développement OSS en un model crowdfunding light.

## Vs alternatives

- **GitHub Sponsors** : gratuit, mais limité en features.
- **Open Collective** : transparence financière forte, idéal pour les collectifs (plusieurs mainteneurs).
- **Patreon** : généraliste, moins adapté à OSS spécifique.
- **Buy Me a Coffee** : très simple, pas de tiers structurés.

Polar.sh est le plus aligné aux workflows dev OSS modernes : intégration GitHub native, payments per-issue, etc.
